# white-label

Rebrand this project end to end with one command.

```bash
npx white-label from: oldbrand to: bright plumbing
```

It sweeps every text file in the repo and swaps the product label wherever it
appears — identifiers, storage keys, package names, domains, e-mail addresses,
dotfiles, tool config, file names, and the prose users actually read. Then it
sweeps a second time to prove nothing was left behind.

## The idea

A brand is never spelled just one way. In a project like this one it shows up as
all of these:

| Spelling | Where |
| --- | --- |
| `oldbrand.ai` | domains, e-mail addresses, page titles |
| `oldbrand-server` | npm package names |
| `oldbrand_token` | `localStorage` keys |
| `oldbrand:boot-reloaded` | namespaced session keys |
| `Oldbrand` | `branding.appName`, e-mail `app_name` |
| `oldbrand` | prose — "a test call summary from oldbrand." |

A plain find-and-replace has to pick one replacement for all of them, and gets
most of them wrong. This tool decides per occurrence.

## How it decides

Every match is classified twice.

**1. By the shape of the matched text.** `OLDBRAND_TOKEN` is SCREAMING_SNAKE, so
it comes out `BRIGHTPLUMBING_TOKEN`. `appOldbrandLogo` is camelCase, so it comes
out `appBrightPlumbingLogo`. Shape is preserved.

**2. By what sits either side of it**, when the shape alone is ambiguous — a
bare lowercase `oldbrand` could be an identifier or a word in a sentence. The
neighbouring characters settle it:

```
"oldbrand_token"       →  "brightplumbing_token"      glued to an identifier
oldbrand.ai            →  brightplumbing.ai           glued to a TLD
support@oldbrand.ai    →  support@brightplumbing.ai   an e-mail local part
5432/oldbrand?schema=  →  5432/brightplumbing?schema= a path segment
…summary from oldbrand. If you…  →  …summary from Bright Plumbing. If you…
```

That last one is the point: a full stop followed by a space ends a sentence, a
full stop followed by a letter starts a TLD. Same characters, opposite answers.

It holds inside dotfiles too. In a `.gitignore`:

```diff
- # Local-only oldbrand notes      →  # Local-only Bright Plumbing notes
- oldbrand-scratch.md              →  brightplumbing-scratch.md
```

A comment is prose; a filename is an identifier.

Two more rules earn their keep:

- **Slug-only files.** In `package.json`, lock files and `.env*` the brand is
  *always* an identifier — writing `"name": "Bright Plumbing"` would be invalid.
  Those files skip the prose branch entirely.
- **Split word-marks.** `oldbrand<span className="text-primary">.ai</span>` is a
  domain wearing markup. The `.ai` on the far side of the tag is detected, so it
  becomes `brightplumbing<span …>.ai</span>` and not `Bright Plumbing<span …>.ai`.

Replacements are written in a single left-to-right pass, so freshly written text
is never rescanned — renaming `acme` to `acme voice` terminates.

## What is in scope

**Everything except build output and dependencies.** Dotfiles and tool config
are swept too, because a repo handed to another business must not carry the
previous brand anywhere:

- `.gitignore`, `.env`, `.env.example`, `.npmrc`, `.github/`
- `.claude/settings.local.json` and anything else under `.claude/`
- `package.json`, lock files, `vercel.json`, SQL migrations, Markdown docs
- file and directory names

Skipped: `.git`, `node_modules`, `dist`, `build`, `coverage` and the other build
directories — plus `tools/white-label` itself, so the tool cannot rewrite its own
fixtures mid-run. (Its fixtures use a stand-in brand, so it carries no real
customer's name.)

## The verification pass

After a run, the tool sweeps again — **build output and skipped directories
included** — and reports anything still carrying the old brand:

```
✔ Verified: no trace of "Oldbrand" left in the repo.
```

or

```
⚠ 47 mentions of "Oldbrand" still present in 17 files:
    server/dist/routes/admin.routes.js 7×
    server/dist/services/sms.test.js 7×
    …
  Build output is regenerated by the next build; anything else needs a look.
```

Stale `dist/` output is the usual culprit and is harmless once you rebuild — but
you find out, rather than shipping it.

## Usage

```
npx white-label from: <old label> to: <new label> [options]
npx white-label to: <new label>      # reuses the brand in white-label.config.json
```

`npm run white-label -- from: oldbrand to: bright plumbing` works too, if you
would rather not rely on the linked bin.

| Option | Effect |
| --- | --- |
| `from: <label>` | Brand to replace. Optional once `white-label.config.json` exists. |
| `to: <label>` | New brand. Multi-word labels are fine — the value runs to the next key. |
| `display: <text>` | Pin the human-readable name. Default: Title Case of `to`. |
| `slug: <text>` | Pin the identifier form. Default: the words squashed together. |
| `domain: <host>` | Pin the new domain, TLD included. Default: `<slug>` + the old TLD. |
| `--dry-run`, `-n` | Print every change without writing anything. |
| `--allow-dirty` | Run with uncommitted changes in the tree. |
| `--no-locks` | Leave `package-lock.json` and friends alone. |
| `--no-rename` | Do not rename files or directories. |
| `--no-config` | Do not write `white-label.config.json`. |
| `--quiet` | Summary only. |

### Derived names

`to: bright plumbing` produces:

| Form | Value | Used for |
| --- | --- | --- |
| display | `Bright Plumbing` | prose, app names, e-mail subjects |
| slug | `brightplumbing` | domains, package names, storage keys |
| pascal | `BrightPlumbing` | components, types |
| camel | `brightPlumbing` | variables |
| kebab | `bright-plumbing` | `bright-plumbing-server` |
| snake | `bright_plumbing` | `bright_plumbing_token` |
| constant | `BRIGHT_PLUMBING` | env vars |

Override the two that matter when the defaults are not what you want:

```bash
npx white-label to: bright plumbing slug: bright-plumbing display: "BrightPlumbing™"
```

### Changing the domain too

By default the TLD is carried over, so `oldbrand.ai` becomes
`brightplumbing.ai`. Pass `domain:` to change the host outright — subdomains are
preserved:

```bash
npx white-label from: oldbrand to: bright plumbing domain: brightplumbing.com.au
# https://app.oldbrand.ai/login  →  https://app.brightplumbing.com.au/login
```

## Shipping a copy to another business

The repeatable recipe:

```bash
git clone <this repo> bright-plumbing && cd bright-plumbing
rm -rf .git && git init                 # start their history clean — see below
npx white-label to: bright plumbing domain: brightplumbing.com.au
npm install && npm --prefix server install
npm run build && npm --prefix server run build
```

Watch for the `✔ Verified` line at the end. If it warns instead, the listed
files still carry the old name.

Three things the command cannot do for you, and one of them is easy to miss:

1. **Git history.** `git log -p` still contains every previous brand — the
   command only rewrites the working tree. Handing over the repo hands over the
   history. `rm -rf .git && git init` above is what actually prevents that.
2. **Secrets in `.env`.** These files are swept for the brand, but they still
   hold live Stripe / Twilio / Vapi / SMTP credentials. Replace the values
   before handing the folder to anyone.
3. **Design and infrastructure.** Logos, favicon and avatars are uploaded
   through the admin panel (they are not in the repo); brand colours live in
   `src/index.css`; DNS, mail domains and third-party accounts are external.

## Safety

- **Refuses to run on a dirty tree** unless you pass `--allow-dirty`, so a sweep
  is always undoable with `git restore .`.
- **`--dry-run` first** prints every file, count and a sample diff per file.
- Binary files, oversized files and symlinks are never touched.
- Word boundaries are enforced, so `theoldbrand22nd` is left alone.
- An explicit `from:` always derives its own variants, so a stale
  `white-label.config.json` can never corrupt the search patterns.

## Configuration

After a successful run the new brand is recorded in `white-label.config.json` at
the repo root, which lets later runs omit `from:`. You can also hand-edit it:

```jsonc
{
  "brand": {
    "name": "bright plumbing",
    "display": "Bright Plumbing",
    "slug": "brightplumbing",
    "domain": "brightplumbing.ai"
  },

  // Literal swaps applied before every other rule — the escape hatch for
  // anything the heuristics get wrong.
  "overrides": {
    "support@brightplumbing.ai": "help@brightplumbing.com.au"
  },

  // Optional. Each replaces the built-in default list entirely.
  "skipDirs": ["node_modules", "dist", ".git"],
  "skipFiles": ["CHANGELOG.md"],
  "slugOnlyFiles": ["package.json", "package-lock.json"]
}
```

## Tests

```bash
npx vitest run --project tools
```

37 tests pin the prose-vs-code decisions against realistic string shapes, so a
regression in the heuristics fails loudly.
